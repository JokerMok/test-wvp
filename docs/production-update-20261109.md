## 更新

1. 将压缩包及其 `.sha256` 文件上传到正式服务器，使用 `sha256sum -c` 核对完整性，解压到独立暂存目录。
2. 原归档带有历史环境配置及运行数据。程序源码、前端和构建模板使用新包，现网 `.env`、数据库、Redis、录像、上传文件、日志及 JWK 持久化目录沿用现有挂载。发布前记录当前 WVP、Nginx 镜像 ID，并为本次涉及的配置保留一个恢复点。
3. 将实际生效的 WVP 外部配置中 `user-settings.login-timeout` 合并为 `1440`。本包已覆盖 `docker/wvp/wvp/application-docker.yml`、`application-base.yml`，以及源码中的开发和 Docker 配置。ZLM 实际挂载配置中将 `[rtp_proxy]` 的 `timeoutSec` 合并为 `3600`。现网 IP、端口、账号和 SIP 参数按现场配置合并。
4. 更新 `docker/nginx/templates/nginx.conf.template`。在部署目录按既有流程构建并切换 WVP、Nginx，让 Nginx 启动时重新生成配置。ZLM 重启后读取新的收流超时值。操作安排在维护时段，既有视频连接会受到服务重启影响。

现场已沿用 11 月 6 日 UDP 配置时，可按以下服务范围操作。首次使用本包的现场还需核对既有 RTP/RTCP 端口映射和来源放行规则。

```sh
docker compose config -q
docker compose build polaris-wvp polaris-nginx
docker compose restart polaris-media
docker compose up -d --no-deps --force-recreate polaris-wvp polaris-nginx
```

发布后退出并重新登录一次，新令牌按 24 小时签发。已签发令牌的到期时间由其原有 `exp` 决定。重新点播并生成分享链接，确认视频地址为 `ws://47.106.174.114:18080/rtp/…`。历史分享链接携带旧端口时，重新生成链接，或将媒体端口改为 18080。

登录后可从 `/api/server/system/configInfo` 的 `addOn.loginTimeout` 核对实际登录配置。ZLM 管理接口 `getServerConfig` 中 `rtp_proxy.timeoutSec` 应为 `3600`。该值针对 RTP 断流等待，首次点播等待和无人观看回收各有独立触发条件。
