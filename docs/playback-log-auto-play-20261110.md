# 点播、实时日志与自动续播更新

本次修复某些通道点播失败后长期停留在“已有请求在途”的问题，恢复正式 Docker 入口的实时日志，并增加后台自动续播。服务器尚未部署此版。

## 使用

管理员在“通道列表”勾选摄像头，点击顶部“自动续播”，保持默认 60 秒并开启所选。任务保存在数据库中，关闭浏览器后继续运行，服务重启后继续检查。所有通道初始均未开启。

- 后台直接查询 ZLM 的流、视频轨道和实时数据速率。流不存在时尝试恢复；连续两次有效检查均无可用视频数据时重新点播。
- 媒体查询失败时显示“状态未知”，不据此关流。设备离线时等待上线。
- 失败后按 30、60、120、300 秒退避，最多同时恢复两路，避免重复 INVITE。
- 通道行的“停止”会先暂停该通道的自动续播，再停止视频。需要重新开启时回到“自动续播”窗口操作。关闭自动续播本身不会停止现有视频。
- 已开启自动续播的源流会在无人观看时保留。预览窗口可在源流恢复后重新连接；窗口内暂停、停止或关闭后，不会被自动打开。

## 升级

先在现有 MySQL 库执行 `数据库/2.7.4/更新-mysql-自动续播-20261110.sql`，再按原有流程构建、切换 WVP 和网页。正式 Docker 入口还须更新 `docker/nginx/templates/nginx.conf.template` 并重建 Nginx；腾讯云继续使用原有 Caddy 入口。

SQL 只创建 `wvp_auto_play` 表，可重复执行，不替换原通道、用户和设备数据。必须先执行迁移，才能保存续播任务和可靠处理人工暂停。

沿用现场数据库、Redis、JWK、SIP 参数及 UDP。登录 24 小时、ZLM RTP 超时 3600 秒保持上一版设置。首次点播等待时间没有延长到 60 分钟。

回退应用时恢复上一版 WVP、网页及入口配置，保留新增表和现有数据即可，旧代码不会运行新续播任务。数据库恢复应按现场备份流程单独处理。

## 验证范围

后端定向用例覆盖过期请求释放、并发去重、旧回调隔离、人工暂停后的迟到结果、两路恢复限制、未知媒体状态和登录鉴权。隔离 MySQL 8.0 验证迁移重复执行、租约及暂停规则；隔离 Tomcat/Nginx 验证新日志帧和匿名拒绝。前端组件检查覆盖 60 秒默认值、勾选范围、日志重连与容量，以及暂停和关闭期间的异步结果。

以上验证不等同于现场摄像头验收。天影云最初为何未注册成可播放媒体，仍需同次点播的 ZLM 日志确认；本次修复平台状态不能释放和后续不能重试的问题。

本轮实际结果：23 项后端定向测试、17 项 MySQL 检查、21 项前端组件检查均通过；基于正式包配置的 Java 21/Maven 3.9.9 后端打包与前端生产构建通过。

仓库的 Maven 配置默认跳过测试。本轮使用 JUnit Platform Launcher 实际执行指定测试类；`mvn package` 的成功记录仅代表构建，不代表执行了测试。前端组件检查可在 `web/` 运行 `node tests/auto-play-log.cjs`。
